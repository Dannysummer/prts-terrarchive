# 双模块检索配方

以下流程只在明日方舟和终末地同时启用时使用。

问题已经明确属于一款游戏时，按对应模块的资料类型做单游戏检索，不必先联合搜索。已知短原句或专名用 `corpus_search`，情节、动机或多资料关系用 `cloud_search` 发现候选，精确结论再回读原文。

## 比较两款游戏中的人物、组织或概念

1. 把比较维度写清楚；可先联合调用默认 `cloud_search` 发现候选。
2. 分别执行 `games:["arknights"]` 与 `games:["endfield"]` 的窄检索，使用各自模块的资料类型，不能用同一个类型数组硬套两边。
3. 各自形成“该游戏资料明示的事实”，再做比较；共同点和差异属于综合结论，不冒充任一侧原文。

## 再旅者与泰拉记忆原型

1. 分别确认两个实体的规范名称和游戏归属。
2. 对任一规范名做检索；结果带 `retraveler_relations` 时，可以将其中的对应关系表述为“PRTS 人工审校关系表登记”，无需强求游戏剧情重复证明该登记。
3. 分别检索双方资料来回答各自身份、经历与表现；不要从登记关系外推同一人物、记忆继承方式或剧情确认程度。
4. 没有 `retraveler_relations`，只有外观、同名或相似经历时，只能说明相似或尚未确认，不能自行建立关系或别名。

## 不确定问题属于哪款游戏

1. 用短专名执行联合 `corpus_search`，或用完整问题执行联合 `cloud_search`。
2. 根据结果的 `game`、资料标题和实体路由确定归属。
3. 归属明确后切换为单游戏范围继续，不让另一侧噪声进入后续核验。

## 联合检索只返回一侧

1. 检查是否出现 `CORPUS_GAME_NOT_INSTALLED`，以及过滤类型是否只属于其中一款游戏。
2. 如果问题要求完整比较，分别使用两边合法类型再检索一次。
3. 仍无一侧证据时明确报告缺口；不要用另一侧材料填补，也不要把零命中写成不存在。

## 双侧时间或剧情对照

明日方舟侧使用 `timeline_search` 或 `story`，终末地侧使用 `resource_types:["timeline"]` 或 `original_story`。先各自建立内部顺序，再比较主题或叙事结构；除非资料明确提供共同纪年关系，不把两套时间直接拼成同一绝对时间轴。
